# __NAME__

A NestJS __TEMPLATE_VERSION__ HTTP service generated by `delonix init -t nestjs`.
It is a small, complete example — not a skeleton: one business capability
(notes) from HTTP request to storage port, signed webhooks in both directions,
OpenTelemetry traces and metrics, structured logs, a readiness state that
follows the process lifecycle, and bounded shutdown.

| | |
|---|---|
| Framework | NestJS __TEMPLATE_VERSION__ on Express 5 — every `@nestjs/*` package on the same major |
| Runtime / language | Node.js 24 LTS, TypeScript 6 (CommonJS output) |
| Package manager | pnpm 11 (pinned in `package.json`, provisioned by corepack) |
| Telemetry | OpenTelemetry JS SDK (`@opentelemetry/sdk-node`), OTLP over HTTP |
| Storage | in memory (`InMemoryNoteRepository`) — replace for real use |
| Contract | `api/openapi.json` (OpenAPI 3.0, generated by `@nestjs/swagger`) |

Limits of the example, stated up front: notes live in memory and vanish on
restart; the inbound webhook de-duplication and the outbound queue are in
memory too (see [docs/adr/0002](docs/adr/0002-webhooks.md)). Nothing here
authenticates API callers — add your platform's mechanism before exposing it.

## Quickstart

Prerequisites: Node.js 24.9 or newer with corepack (`corepack enable` once);
`curl` for the smoke test; Delonix to build and run the image.

```bash
pnpm install                      # resolves and writes pnpm-lock.yaml
git add pnpm-lock.yaml            # commit it: CI installs with --frozen-lockfile
pnpm check                        # format, lint, typecheck, tests, build
pnpm start &                      # the built service (dist/), with telemetry loaded
pnpm smoke                        # health, create/get, 422, 400, 404 → "smoke: OK"
kill %1                           # SIGTERM → ordered shutdown, exit 0
```

The project is generated without a lock file: `-v` changes the dependency
ranges, so a shipped lock would be stale. The first `pnpm install` writes
`pnpm-lock.yaml`; commit it. Until it is committed, CI fails with a message
saying so.

## Layout

```
src/main.ts               composition root: config, logger, listen, signals, shutdown
src/instrumentation.ts    loaded with `node --require` before Nest: starts OpenTelemetry
src/app.module.ts         root module, built from the validated configuration
src/app.setup.ts          the application as it runs (middleware, body parser) — used by main and tests
src/notes/                the capability: entity and rules, use cases (NotesService),
                          ports (NoteRepository, NotePublisher), in-memory adapter, controller, DTOs
src/webhooks/             Standard Webhooks signing/verification, inbound controller, outbound dispatcher
src/health/               readiness state (starting → ready → draining), probes
src/http/                 request id, access log, validation pipe, the exception filter (one error shape)
src/telemetry/            OpenTelemetry setup, use-case spans, route naming
src/logging/              JSON logger (Nest LoggerService), redaction, trace correlation
src/config/               typed, validated configuration
src/architecture.spec.ts  dependency-direction rules as a test
test/                     HTTP tests through the real application, contract drift, one-trace
api/openapi.json          HTTP contract (checked in; compared with the code by a test)
deploy/otel-collector.yaml  local Collector for development
```

[ARCHITECTURE.md](ARCHITECTURE.md) has the dependency rules and a worked
example of extending the capability.

## Configuration

All from the environment; validated at startup (every error listed at once,
the process exits 1 before listening). See [.env.example](.env.example).

| Variable | Purpose | Default | Required | Sensitive |
|---|---|---|---|---|
| `APP_ENV` | `development`, `test`, `production` | `development` | no | no |
| `LOG_LEVEL` | `debug`, `info`, `warn`, `error` | `info` | no | no |
| `PORT` / `HTTP_HOST` | listen address | `__PORT__` / `0.0.0.0` | no | no |
| `HTTP_REQUEST_TIMEOUT`, `HTTP_HEADERS_TIMEOUT`, `HTTP_KEEP_ALIVE_TIMEOUT` | server timeouts | `15s`, `5s`, `60s` | no | no |
| `HTTP_MAX_BODY_BYTES` | request body limit | `1048576` | no | no |
| `SHUTDOWN_TIMEOUT` | bound of the whole shutdown | `15s` | no | no |
| `DRAIN_DELAY` | time serving with readiness at 503 before closing | `0s` | no | no |
| `SERVICE_NAME` | service name in logs and telemetry | `__NAME__` | no | no |
| `APP_VERSION` | version in logs and telemetry (the image sets it from `--build-arg VERSION`) | `dev` | no | no |
| `WEBHOOK_INBOUND_SECRET` | `whsec_<base64>`; enables the inbound endpoint | — | no | **yes** |
| `WEBHOOK_TARGET_URL` | receiver of `note.created` (https in production) | — | no | no |
| `WEBHOOK_TARGET_SECRET` | `whsec_<base64>`; required with the URL | — | with URL | **yes** |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP/HTTP collector, e.g. `http://collector:4318` | — (no export) | no | no |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | sampling | SDK default (parent-based, always on) | no | no |
| `OTEL_SDK_DISABLED` | `true` disables telemetry | — | no | no |

Durations are written `500ms`, `15s`, `1m`. Secrets come from the environment
only: locally from `.env` (git-ignored), in Delonix from a secret
(`delonix secret create`, see the manifest comment). Production
(`APP_ENV=production`) refuses the development shortcuts: an `http://` webhook
target, and the interactive API documentation (`/api/docs`, development only).

## API

Base `http://localhost:__PORT__`. Contract: [api/openapi.json](api/openapi.json).
Every error has one shape: `{"error":{"code","message","fields"?,"request_id"}}`
with codes `validation_failed` (422), `malformed_json` (400), `body_too_large`
(413), `not_found` (404), `internal` (500, no stack).

```bash
curl -si -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' \
  -d '{"title":"hello","body":"world"}'
# 201, Location: /api/v1/notes/<id>, {"id":"…","title":"hello","body":"world","created_at":"…"}
curl -s 'localhost:__PORT__/api/v1/notes?offset=0&limit=20'
# {"items":[…],"total":1,"offset":0,"limit":20}
curl -s -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' -d '{"title":""}'
# 422 {"error":{"code":"validation_failed","message":"invalid input","fields":{"title":"is required"},"request_id":"…"}}
```

Unknown properties and unknown query parameters are refused with 422
(`"is not allowed"`). Versioning: breaking changes go to `/api/v2`; `/api/v1`
changes are additive. `test/openapi.e2e-spec.ts` fails when the code and
`api/openapi.json` drift; `pnpm openapi:write` regenerates the file.

## Webhooks (both directions)

Format: [Standard Webhooks](https://www.standardwebhooks.com) — headers
`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64 HMAC-SHA256>`
over `<id>.<timestamp>.<raw body>`.

- **Inbound** `POST /api/v1/webhooks/inbound` (only with
  `WEBHOOK_INBOUND_SECRET`; `Content-Type: application/json`): verifies over
  the raw bytes kept by the body parser (`rawBody: true`), refuses timestamps
  more than 5 minutes off (replay window), compares in constant time,
  acknowledges a repeated `webhook-id` without processing it again, limits the
  body to 256 KiB. Events: `ping`, `note.create` (runs the same use case as
  the API).
- **Outbound** (only with `WEBHOOK_TARGET_URL`): each created note is sent as
  `note.created`, `webhook-id` = note id (the receiver's idempotency key),
  5 s timeout per attempt (`AbortSignal.timeout`), up to 4 attempts with
  exponential backoff and full jitter on network errors, 429 and 5xx; other
  4xx are final. Deliveries are counted in the `webhook.deliveries{outcome}`
  metric and logged.
- **Delivery semantics**: at-least-once while the process lives; events queued
  at shutdown are drained within `SHUTDOWN_TIMEOUT`, what remains is lost; a
  full queue (100) drops and counts. Never exactly-once. For durable delivery,
  see [docs/adr/0002](docs/adr/0002-webhooks.md).

Sign a test delivery by hand:

```bash
SECRET=whsec_$(head -c 32 /dev/urandom | base64); export WEBHOOK_INBOUND_SECRET=$SECRET
# restart the service, then:
ID=msg_1; TS=$(date +%s); BODY='{"type":"ping"}'
KEY=$(printf %s "${SECRET#whsec_}" | base64 -d | xxd -p -c 256)
SIG=$(printf '%s.%s.%s' "$ID" "$TS" "$BODY" | openssl dgst -sha256 -mac HMAC -macopt hexkey:$KEY -binary | base64)
curl -si -X POST localhost:__PORT__/api/v1/webhooks/inbound -H 'Content-Type: application/json' \
  -H "webhook-id: $ID" -H "webhook-timestamp: $TS" -H "webhook-signature: v1,$SIG" -d "$BODY"   # 204
```

## Logs, traces, metrics

- Logs: JSON on stdout, one line per event, with `service`, `version`,
  `environment`, and `trace_id`/`span_id` inside a request; the access line
  adds `request_id`. Keys containing `authorization`, `cookie`, `password`,
  `secret`, `token`, `signature` or `api_key` are replaced by `[REDACTED]`.
  Query strings, headers and bodies are never logged. Health probes log at
  `debug`. Nest's own lines go through the same logger.
- Traces: one trace per request — the HTTP server span (named by the route
  template), a `notes.*` span for the use case, and `webhook.deliver` plus the
  outbound HTTP span as children, so the outbound call shares the request's
  trace id (`traceparent` is sent to the receiver). Health probes are not
  traced.
- Metrics: the HTTP instrumentation's server/client metrics labelled by route
  template (never by raw path), and `webhook.deliveries`.
- Without `OTEL_EXPORTER_OTLP_ENDPOINT` nothing is exported, but trace ids
  still appear in logs. A collector that is down costs dropped batches, not
  requests. Maturity: traces and metrics are stable in the JS SDK; logs go
  through the logger, not the OTel logs SDK. The telemetry is started by
  `src/instrumentation.ts`, loaded with `node --require` before Nest — running
  `node dist/main.js` alone works but logs a warning and records no spans.

Local collector: [docs/runbooks/operations.md](docs/runbooks/operations.md#observability).

## Lifecycle

`/api/v1/health/live` answers 200 while the process runs. `/api/v1/health/ready`
is 503 `starting` until the listener is up, 200 `ready`, and 503 `draining`
from the first SIGTERM/SIGINT. Shutdown order: readiness → `DRAIN_DELAY` →
then, within `SHUTDOWN_TIMEOUT`: stop accepting and finish in-flight requests
→ drain the webhook queue → flush telemetry. Exit 0 when that completed, 1
when the deadline cut it; a second signal kills at once. No persistence, so
no migrations.

## Build and deploy with Delonix

```bash
delonix build -t __NAME__:dev .       # two stages; .dockerignore is honoured
delonix stack apply                   # delonix-manifest.yaml
curl localhost:__PORT__/api/v1/health/ready
delonix stack destroy                 # removes what the manifest created
```

The manifest publishes `__PORT__`, sets `APP_ENV=production`, 512M/1 CPU,
read-only root filesystem with a `/tmp` tmpfs, and `restart: always`.
The image runs as the unprivileged user `node` (uid 1000), which owns nothing
in the image. The manifest names it (`user:`) because the engine applies an
image's USER only when asked — see
[docs/adr/0003](docs/adr/0003-container-image.md). The
image installs from `pnpm-lock.yaml` when the context has one and resolves
otherwise. Other engines can build the `Delonixfile` as a Dockerfile, but only
Delonix is the target here.

## Tests and CI

`pnpm test` runs two Jest projects. `unit` (`src/**/*.spec.ts`): use cases
through Nest's testing module, configuration, logger (redaction, trace ids),
signature/replay/de-duplication, dispatcher retry/backoff/timeout/shutdown,
and the architecture test. `e2e` (`test/*.e2e-spec.ts`): HTTP through the real
application with supertest (happy path, every error class, pagination, body
limit, readiness transitions), inbound webhooks over raw bytes, the OpenAPI
drift test, and the one-trace test, which starts the compiled service as a
separate process with the production command and checks request → use case →
outbound call → log lines against a fake collector. CI
(`.github/workflows/ci.yml`, `.gitlab-ci.yml`) runs `pnpm check` and
`pnpm audit --prod`, with a read-only token and actions pinned by SHA;
Dependabot updates npm packages, actions and the base image.

## Choosing a NestJS version

`delonix init -t nestjs -v 11` or `-v 12` (default). Every `@nestjs/*` package
— core, common, platform-express, swagger, testing and the CLI — is pinned to
`^__TEMPLATE_VERSION__`; mixing majors is not a supported NestJS install.
NestJS 12 ships as ES modules; this project compiles to CommonJS and loads
them with Node's `require(esm)`, which is why Node 24.9+ is required and why
Jest runs with `--experimental-vm-modules` (see
[docs/adr/0004](docs/adr/0004-commonjs-jest.md)).

## On the internet without a public IP

`delonix-tunnel.yaml` opens an OUTBOUND tunnel: __NAME__ gets an `https`
address on the internet with no public IP, nothing opened on the router, and
no certificate to manage — the provider serves HTTPS with its own. It runs
only when applied; `stack apply` on `delonix-manifest.yaml` does not touch it.
Anyone on the internet can then reach the service.

### Just a tunnel (no account, no domain)

1. Install `cloudflared` ([releases](https://github.com/cloudflare/cloudflared/releases),
   or your distribution's package) somewhere on `PATH`.
2. `delonix stack apply -f delonix-tunnel.yaml`
3. `delonix get gateways` — the address is in `PUBLIC URL`.

The address is random (`https://<words>.trycloudflare.com`) and changes every
time the tunnel opens; Cloudflare offers these quick tunnels for testing,
without an uptime guarantee. Close it with
`delonix delete gateways __NAME__-tunnel`.

### Your own domain (a stable address)

The domain's DNS has to be on Cloudflare (a free account is enough: point the
domain's name servers, at your registrar, to the two Cloudflare gives you).

1. Cloudflare dashboard → Zero Trust → Networks → Tunnels → **Create a
   tunnel** → Cloudflared. Name it and copy the token from the install
   command it shows (`--token eyJ…`).
2. In the tunnel, add a **public hostname**: `app.example.org` → service
   `http://localhost:__PORT__`. Cloudflare creates the DNS record.
3. Keep the token in a Delonix secret, typed in so it lands in no file and
   no shell history: run `delonix secret create __NAME__-tunnel --from-env-file -`,
   type `token=<the token>`, then Enter and Ctrl-D.
4. In `delonix-tunnel.yaml`, uncomment `tokenSecretRef` and `hostname`, then
   `delonix stack apply -f delonix-tunnel.yaml`.

Visitors get Cloudflare's certificate for `app.example.org`. To change the
route later, change it in the dashboard: with a token the tunnel takes its
routes from there, not from this file.

### Other providers

`provider:` also takes:

- `ngrok`: the ngrok agent on `PATH` and an account
  (`ngrok config add-authtoken <token>`). A free account has one fixed name
  (`<words>.ngrok-free.dev`): a stable address without a domain of your own.
  One ngrok tunnel at a time per machine.
- `pinggy`: nothing to install (plain `ssh`), a URL valid for 60 minutes, and a warning page shown to browsers before the site.

## Troubleshooting

| Symptom | Cause |
|---|---|
| exits with `configuration:` and a list | an invalid variable — the message names each |
| CI fails at "The lock file must be committed" | run `pnpm install` once and commit `pnpm-lock.yaml` |
| `pnpm install` fails with `ERR_PNPM_IGNORED_BUILDS` | a new dependency has an install script: review it and add it to `allowBuilds` in `pnpm-workspace.yaml` |
| Jest: `Must use import to load ES Module` | Jest was started without `--experimental-vm-modules` (use `pnpm test`), or Node is older than 24.9 |
| `telemetry not loaded` warning, no `trace_id` in logs | started without `--require ./dist/instrumentation.js` (use `pnpm start`) |
| inbound webhook answers 401 | wrong secret, body re-encoded by a proxy, or clock skew over 5 minutes |
| `/api/v1/webhooks/inbound` is 404 | `WEBHOOK_INBOUND_SECRET` is not set |
| no traces in the collector | `OTEL_EXPORTER_OTLP_ENDPOINT` unset, or not the `:4318` HTTP port |
