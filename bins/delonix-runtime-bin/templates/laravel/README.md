# __NAME__

A Laravel __TEMPLATE_VERSION__ HTTP service generated by `delonix init -t laravel`,
served by FrankenPHP on PHP 8.4. It is a small, complete example — not a
skeleton: one business capability (notes) from HTTP request to database,
signed webhooks in both directions (outbound through Laravel's queue),
OpenTelemetry traces, structured logs, readiness that follows the lifecycle,
and a container that refuses to start on a bad configuration.

| | |
|---|---|
| Framework / runtime | Laravel __TEMPLATE_VERSION__ (`composer.json`), PHP 8.4, FrankenPHP 1 (`Delonixfile`) |
| Persistence | Eloquent + migrations, SQLite by default (`DB_CONNECTION` for others) |
| Queue | Laravel `database` queue (`jobs` table), `php artisan queue:work` |
| Telemetry | OpenTelemetry PHP SDK 1.x, manual instrumentation, traces only |
| Contract | `api/openapi.yaml` (OpenAPI 3.1) |

Limits of the example, stated up front: SQLite is one file on one volume, so
one web container and one worker (move to PostgreSQL/MySQL to scale out);
delivery of outbound webhooks is at-least-once; there are no metrics and
database queries are not traced ([docs/adr/0004](docs/adr/0004-telemetry.md)).
Nothing here authenticates API callers — add your platform's mechanism
before exposing it.

## Quickstart

Prerequisites: PHP 8.4 with `pdo_sqlite` (`pcntl` is optional: with it the queue
worker finishes the job in hand on SIGTERM),
Composer 2, `curl`; Delonix to build and run the image.

```bash
composer install                  # resolves and writes composer.lock — commit it
cp .env.example .env
composer check                    # format, lint, static analysis, tests
composer serve &                  # check config, migrate, listen on :__PORT__
composer smoke                    # health, create/get/list, 422, 400, 404 → "smoke: OK"
kill %1
```

`composer.lock` is not generated by `delonix init` (it depends on the `-v`
you chose). CI fails with a message until it is committed; the image build
resolves on its own when the lock is absent and warns.

## Layout

```
app/Notes/            the capability: Note, use cases (NoteService), ports — plain PHP
app/Http/             controllers, Form Requests, middleware, the error shape
app/Persistence/      EloquentNoteRepository (adapter of NoteRepository)
app/Models/           Eloquent rows: Note, WebhookReceipt
app/Webhooks/         Standard Webhooks signing/verification, inbound processor, publisher
app/Jobs/             DeliverWebhook (queued outbound delivery)
app/Telemetry/        tracer provider, use-case spans, HTTP client spans
app/Logging/          JSON formatter, redaction, trace correlation
app/Support/          ConfigValidator
app/Providers/        composition root (ports → adapters), telemetry wiring
config/               service.php (this service), overrides of Laravel defaults
database/migrations/  notes, webhook_receipts, jobs + failed_jobs
routes/api.php        the routes (mounted under /api)
api/openapi.yaml      HTTP contract (source of truth for the routes)
Caddyfile, docker/    FrankenPHP configuration and the container entrypoint
deploy/otel-collector.yaml  local Collector for development
```

## Configuration

All from the environment (`.env` locally). `php artisan app:check-config`
validates everything and lists every problem; the container entrypoint runs
it and exits 1 before anything listens. See [.env.example](.env.example).

| Variable | Purpose | Default | Required | Sensitive |
|---|---|---|---|---|
| `APP_ENV` | `development`, `test`, `production` | `production` | no | no |
| `APP_KEY` | Laravel encryption key (`base64:` + 32 bytes) | — | **in production** | **yes** |
| `APP_DEBUG` | must be `false` in production (refused otherwise) | `false` | no | no |
| `LOG_LEVEL` | `debug`, `info`, `notice`, `warning`, `error` | `info` | no | no |
| `PORT` | listen port of the image (Caddyfile) | `__PORT__` | no | no |
| `HTTP_MAX_BODY_BYTES` | request body limit of the API | `1048576` | no | no |
| `SHUTDOWN_TIMEOUT` | grace period for in-flight requests | `15s` | no | no |
| `DRAIN_DELAY` | time serving with readiness at 503 before closing | `0s` | no | no |
| `DB_CONNECTION` / `DB_DATABASE` | database driver / SQLite file | `sqlite` / `database/database.sqlite` (image: `/var/lib/app/database.sqlite`) | no | no |
| `QUEUE_CONNECTION` | queue driver | `database` | no | no |
| `SERVICE_NAME` | name in logs and telemetry | `__NAME__` | no | no |
| `WEBHOOK_INBOUND_SECRET` | `whsec_<base64>`; enables the inbound endpoint | — | no | **yes** |
| `WEBHOOK_TARGET_URL` | receiver of `note.created` (https in production) | — | no | no |
| `WEBHOOK_TARGET_SECRET` | `whsec_<base64>`; required with the URL | — | with URL | **yes** |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP/HTTP collector, e.g. `http://collector:4318` | — (no export) | no | no |
| `OTEL_EXPORTER_OTLP_TIMEOUT` | export timeout, milliseconds | `2000` | no | no |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | sampling | `parentbased_always_on` | no | no |
| `OTEL_SDK_DISABLED` | `true` disables telemetry | — | no | no |

`APP_ENV` uses the contract's names, not Laravel's `local`/`testing`.
Secrets come from the environment only: locally from `.env` (git-ignored), in
Delonix from a secret (see the manifest). `APP_KEY` is never generated at
build time and never stored in the image.

## API

Base `http://localhost:__PORT__`. Contract: [api/openapi.yaml](api/openapi.yaml).
Every error has one shape: `{"error":{"code","message","fields"?,"request_id"}}`
with codes `validation_failed` (422), `malformed_json` (400), `body_too_large`
(413), `not_found` (404), `method_not_allowed` (405), `internal` (500, never a
stack trace).

```bash
curl -si -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' \
  -d '{"title":"hello","body":"world"}'
# 201, Location: /api/v1/notes/<id>, {"id":"…","title":"hello","body":"world","created_at":"…"}
curl -s 'localhost:__PORT__/api/v1/notes?offset=0&limit=20'
# {"items":[…],"total":1,"offset":0,"limit":20}
curl -s -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' -d '{"title":""}'
# 422 {"error":{"code":"validation_failed","message":"invalid input","fields":{"title":"The title field is required."},"request_id":"…"}}
```

Send `Content-Type: application/json`. Unknown fields are refused. Versioning:
breaking changes go to `/api/v2`; `/api/v1` changes are additive.
`tests/Feature/OpenApiContractTest.php` fails when routes and contract drift.

## Webhooks (both directions)

Format: [Standard Webhooks](https://www.standardwebhooks.com) — headers
`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64 HMAC-SHA256>`
over `<id>.<timestamp>.<raw body>`.

- **Inbound** `POST /api/v1/webhooks/inbound` (only with
  `WEBHOOK_INBOUND_SECRET`; 404 otherwise): verifies over the raw bytes
  (`$request->getContent()`), refuses timestamps more than 5 minutes off,
  compares with `hash_equals`, limits the body to 256 KiB. A repeated
  `webhook-id` is acknowledged (204) without running again: the id is a
  primary key in `webhook_receipts`, written in the same transaction as the
  effect, so de-duplication survives restarts and is shared by replicas.
  Events: `ping`, `note.create` (runs the same use case as the API).
- **Outbound** (only with `WEBHOOK_TARGET_URL`): each created note queues a
  `DeliverWebhook` job; **a worker must run** (`php artisan queue:work`; the
  manifest runs it as the `__NAME__-worker` container). `webhook-id` = note id
  (the receiver's idempotency key), 5 s timeout per attempt, 4 attempts with
  full-jitter backoff (up to 2 s, 4 s, 8 s) on network errors, 429 and 5xx;
  other 4xx are final. Exhausted deliveries are in `failed_jobs`
  (`php artisan queue:failed`, `queue:retry`).
- **Delivery semantics**: at-least-once. Queued jobs survive restarts; a
  worker killed mid-delivery repeats that delivery after 90 s. Never
  exactly-once. See [docs/adr/0002](docs/adr/0002-webhooks.md).

Sign a test delivery by hand:

```bash
SECRET=whsec_$(head -c 32 /dev/urandom | base64)
# put WEBHOOK_INBOUND_SECRET=$SECRET in .env, restart the service, then:
ID=msg_1; TS=$(date +%s); BODY='{"type":"ping"}'
KEY=$(printf %s "${SECRET#whsec_}" | base64 -d | xxd -p -c 256)
SIG=$(printf '%s.%s.%s' "$ID" "$TS" "$BODY" | openssl dgst -sha256 -mac HMAC -macopt hexkey:$KEY -binary | base64)
curl -si -X POST localhost:__PORT__/api/v1/webhooks/inbound -H "webhook-id: $ID" \
  -H "webhook-timestamp: $TS" -H "webhook-signature: v1,$SIG" -d "$BODY"   # 204
```

## Logs, traces, metrics

- **Logs**: JSON on stdout, one line per event, with `service`, `version`,
  `environment`, `request_id`, and `trace_id`/`span_id` inside a request or a
  job (the request id follows the job through the queue via Laravel's
  Context). Keys containing `authorization`, `cookie`, `password`, `secret`,
  `token`, `signature`, `api_key` are replaced by `[REDACTED]`. Query strings,
  headers and bodies are never logged. Health probes log at `debug`.
- **Traces**: one trace per request — the server span (named by route
  template), a `notes.*` span for the use case, and, in the worker,
  `webhook.deliver` plus the HTTP client span, all with the request's trace
  id; the outbound call carries `traceparent`. Health probes are not traced.
- **Metrics**: none. PHP shares no memory between requests here, so SDK
  counters would restart at every request; derive request metrics from spans
  in the Collector.
- Without `OTEL_EXPORTER_OTLP_ENDPOINT` nothing is exported, but trace ids
  still appear in logs. Export happens after the response is sent; a
  collector that is down costs a logged export error and at most
  `OTEL_EXPORTER_OTLP_TIMEOUT` of PHP time per request, not a failed request.
- **Maturity**: the OpenTelemetry PHP API and SDK are stable; instrumentation
  here is manual (three classes in `app/Telemetry`, one middleware). The
  automatic Laravel instrumentation is beta and needs a PECL extension — not
  used ([docs/adr/0004](docs/adr/0004-telemetry.md)).

Local collector: [docs/runbooks/operations.md](docs/runbooks/operations.md#observability).

## Lifecycle and migrations

Container start (`docker/entrypoint.sh`): validate configuration → cache it
(from the runtime environment, into `/tmp`) → `php artisan migrate --force` →
FrankenPHP listens. Until then the port refuses connections.

`/api/v1/health/live` is 200 while PHP answers. `/api/v1/health/ready` is 200
`ready`; 503 `starting` when the schema is not migrated, 503 `unavailable`
(`"dependency":"database"`) when the database cannot be opened, and 503
`draining` after SIGTERM while `DRAIN_DELAY` runs.

SIGTERM/SIGINT (FrankenPHP): readiness turns 503 for `DRAIN_DELAY`, then the
listener closes and in-flight requests get up to `SHUTDOWN_TIMEOUT`; exit 0.
With the default `DRAIN_DELAY=0s` the listener closes at once, so a probe
sees a refused connection rather than a 503. The worker finishes the job in
hand, then exits. Details and measurements:
[docs/runbooks/operations.md](docs/runbooks/operations.md#shutdown).

Schema changes are new files in `database/migrations/`; the web container
applies them at start. Migrations must stay compatible with the previous
image while both run.

## Build and deploy with Delonix

```bash
delonix secret create __NAME__-app --from-literal "APP_KEY=base64:$(head -c 32 /dev/urandom | base64)"
delonix build -t __NAME__:dev .       # two stages; .dockerignore is honoured
delonix stack apply                   # delonix-manifest.yaml: web + worker + volume
curl localhost:__PORT__/api/v1/health/ready
delonix stack destroy                 # removes what the manifest created
```

The manifest runs the web container (port `__PORT__`, 512M/1 CPU) and the
worker (256M), both with a read-only root filesystem, sharing the
`__NAME__-data` volume that holds the SQLite file. The secret must exist
before `stack apply` (so `delonix init --up` needs it too). The image runs
as uid 0 inside the container; with rootless Delonix that uid is your
unprivileged host user — see [docs/adr/0003](docs/adr/0003-container-image.md).
Other engines can build the `Delonixfile` as a Dockerfile.

## Tests and CI

`composer test` runs PHPUnit: use-case tests without framework or database,
signature tests (including the specification's reference vector),
configuration and log-format tests, feature tests through the HTTP kernel
against in-memory SQLite (happy path, every error class, pagination, body
limit, readiness states, inbound verification/replay/duplicates, outbound
retry classes and backoff), the one-trace test (request → use case → queue →
outbound call → log lines), the OpenAPI drift test and the architecture
test. CI (`.github/workflows/ci.yml`, `.gitlab-ci.yml`) requires
`composer.lock`, installs from it, and runs format check, lint, static
analysis, tests and `composer audit`, with a read-only token and actions
pinned by SHA; Dependabot updates Composer packages, actions and base images.

## Troubleshooting

| Symptom | Cause |
|---|---|
| container exits with `configuration:` and a list | an invalid variable — each line names one |
| `APP_KEY: required in production` | create the secret (see Build and deploy) |
| CI: `composer.lock is missing` | run `composer install` once and commit the lock |
| `Composer detected issues in your platform` | PHP older than 8.4; the lock is resolved for 8.4 |
| notes are created but no webhook arrives | no worker running, or `WEBHOOK_TARGET_URL` unset; check `php artisan queue:failed` |
| inbound webhook answers 401 | wrong secret, body re-encoded by a proxy, or clock skew over 5 minutes |
| `/api/v1/webhooks/inbound` is 404 | `WEBHOOK_INBOUND_SECRET` is not set |
| ready is 503 `starting` | migrations not applied (`php artisan migrate`) |
| no traces in the collector | `OTEL_EXPORTER_OTLP_ENDPOINT` unset, or not the `:4318` HTTP port |

## Choosing a Laravel version

`delonix init -t laravel -v 12` (or `13`, the default) sets
`laravel/framework: ^<version>` in `composer.json`; PHP 8.4 runs both. Laravel
support dates: <https://laravel.com/docs/releases#support-policy>.
