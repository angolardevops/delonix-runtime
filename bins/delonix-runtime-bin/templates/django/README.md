# __NAME__

A Django JSON service generated by `delonix init -t django` (Django
__TEMPLATE_VERSION__, Python 3.13, uv). It is a small, complete example — not
a skeleton: one business capability (notes) from HTTP request to the
database, signed webhooks in both directions, OpenTelemetry traces and
metrics, structured logs, a readiness state that follows the process
lifecycle and the database, and a bounded graceful shutdown under gunicorn.

| | |
|---|---|
| Framework | Django __TEMPLATE_VERSION__ (`django==__TEMPLATE_VERSION__.*` in `pyproject.toml`), plain function views — no DRF |
| Runtime | Python 3.13 (`.python-version`, `python:3.13-slim`), gunicorn (`gthread` workers) |
| Dependencies | uv (`pyproject.toml`; `uv.lock` is generated by you — see Quickstart) |
| Storage | Django ORM; SQLite by default, PostgreSQL through `DATABASE_URL` |
| Telemetry | OpenTelemetry Python SDK, Django and httpx instrumentation, OTLP/HTTP |
| Contract | `api/openapi.yaml` (OpenAPI 3.1) |

Limits of the example, stated up front: SQLite serves one replica; the
outbound webhook queue lives in memory (see
[docs/adr/0002](docs/adr/0002-webhooks.md)); nothing here authenticates API
callers — add your platform's mechanism before exposing it.

## Quickstart

Prerequisites: [uv](https://docs.astral.sh/uv/) (it installs Python 3.13
itself), `make`, `curl`; Delonix to build and run the image.

```bash
uv lock                           # writes uv.lock — COMMIT IT (CI installs with --locked and fails without it)
make install                      # .venv with runtime and dev dependencies
make check                        # format, lint, migration drift, deploy checklist, tests
make migrate                      # create the SQLite database (explicit step, see below)
uv run gunicorn config.wsgi:application &   # what `make run` runs, on :__PORT__ (`make dev` for autoreload)
make smoke                        # health, create/get/list, 422, 404 → "smoke: OK"
kill %1                           # SIGTERM → drain, exit 0
```

(`make run` in the foreground is the same server; stop that one with a
SIGTERM to the gunicorn master, not to `make` — Ctrl-C is gunicorn's fast
shutdown, without draining.)

The template ships no `uv.lock` because `-v` changes the dependency ranges;
the first `uv lock` resolves them for the Django line you chose.

## Commands

| Task | Command |
|---|---|
| Install dependencies | `make install` (`uv sync`) |
| Re-resolve / upgrade | `make lock` (`uv lock`), `uv lock --upgrade` |
| Add a dependency | `uv add <package>` |
| Run in development | `make dev` (`manage.py runserver`, autoreload, no graceful shutdown) |
| Run as in production | `make run` (gunicorn + `gunicorn.conf.py`) |
| Migrations | `make migrate`; create one with `uv run python manage.py makemigrations` |
| Format / check format | `make fmt` / `make fmt-check` (ruff format) |
| Lint | `make lint` (ruff check, including import order and bandit-style `S` rules) |
| Tests (unit, integration, contract, architecture, trace) | `make test` |
| Model/migration drift | `make migrations-check` |
| Deployment checklist | `make deploy-check` (`manage.py check --deploy --fail-level WARNING` with production settings) |
| Vulnerabilities | `make vuln` (pip-audit over the locked dependencies; needs network) |
| Smoke a running instance | `make smoke URL=http://localhost:__PORT__` |
| Everything CI runs | `make check` then `make vuln` |

There is no separate type checker: Django's ORM is dynamic enough that mypy
needs `django-stubs` and its plugin to say anything useful, and for a service
this size ruff's checks plus the tests cover what it would catch. Type hints
are written throughout; add `mypy` + `django-stubs` when the codebase grows.

## Layout

```
config/env.py         typed, validated configuration (plain Python; gunicorn reads it too)
config/settings.py    Django settings built from it
config/urls.py        the route table
config/wsgi.py        WSGI entry: telemetry, application, readiness
gunicorn.conf.py      server: workers, graceful shutdown hooks, JSON logs
core/                 cross-cutting: error shape, strict JSON, middleware, readiness, logging, telemetry
notes/                the capability: models (ORM), services (use cases), views, urls, signals
webhooks/             Standard Webhooks: signature, inbound endpoint + de-duplication, outbound dispatcher
tests/                unit, integration, contract drift, architecture and one-trace tests
api/openapi.yaml      HTTP contract (source of truth for the routes)
deploy/otel-collector.yaml  local Collector for development
```

[ARCHITECTURE.md](ARCHITECTURE.md) has the dependency rules, the concessions
made to Django's idiom, and a worked example of extending the capability.

## Configuration

All from the environment, parsed and validated at startup by `config/env.py`
(every error listed at once; the process exits before listening). See
[.env.example](.env.example). "Prod" = required when `APP_ENV=production`.

| Variable | Purpose | Default | Required | Sensitive |
|---|---|---|---|---|
| `APP_ENV` | `development`, `test`, `production` | `development` | no | no |
| `LOG_LEVEL` | `debug`, `info`, `warning`, `error` | `info` | no | no |
| `PORT` / `HTTP_HOST` | gunicorn listen address | `__PORT__` / `0.0.0.0` | no | no |
| `WEB_CONCURRENCY` / `GUNICORN_THREADS` | worker processes / threads per worker | `2` / `4` | no | no |
| `SHUTDOWN_TIMEOUT` | bound of the whole shutdown (`15s`, `500ms`, `2m`) | `15s` | no | no |
| `DRAIN_DELAY` | time serving with readiness at 503 before closing | `0s` | no | no |
| `HTTP_MAX_BODY_BYTES` | request body limit | `1048576` | no | no |
| `SERVICE_NAME` | service name in logs and telemetry | `__NAME__` | no | no |
| `SECRET_KEY` | Django's signing key; production refuses a missing or guessable one (< 50 chars, < 5 distinct, `django-insecure-…`) | development-only constant | Prod (or the file) | **yes** |
| `SECRET_KEY_FILE` | file holding the key, used when `SECRET_KEY` is unset; created with a random key (mode 0600) on first use | — | no | **yes** (the file) |
| `ALLOWED_HOSTS` | comma-separated host names; production refuses empty and `*` | `localhost,127.0.0.1,[::1]` | Prod | no |
| `DATABASE_URL` | `sqlite:///path` or `postgres://user:pass@host:5432/name` | `sqlite:///<project>/db.sqlite3` | Prod | **yes** (password) |
| `TRUSTED_PROXY` | address(es) of the TLS-terminating proxy; enables `X-Forwarded-Proto` | — | no | no |
| `SECURE_SSL_REDIRECT` | redirect plain HTTP to https | `true` in production | no | no |
| `SECURE_HSTS_SECONDS`, `SECURE_HSTS_INCLUDE_SUBDOMAINS`, `SECURE_HSTS_PRELOAD` | HSTS header | `31536000`, `true`, `false` in production; off otherwise | no | no |
| `WEBHOOK_INBOUND_SECRET` | `whsec_<base64>`; enables the inbound endpoint | — | no | **yes** |
| `WEBHOOK_TARGET_URL` | receiver of `note.created` (https in production) | — | no | no |
| `WEBHOOK_TARGET_SECRET` | `whsec_<base64>`; required with the URL | — | with URL | **yes** |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP/HTTP collector, e.g. `http://collector:4318` | — (no export) | no | no |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | sampling | SDK default (parent-based, always on) | no | no |
| `OTEL_SDK_DISABLED` | `true` disables telemetry | — | no | no |

`DEBUG` is not configurable: it is always off (errors are answered in the
API's error shape, and Django's debug pages would expose settings).

Secrets come from the environment only: locally from `.env` (git-ignored), in
Delonix from a secret (`delonix secret create`, see the manifest comment).
`SECRET_KEY_FILE` suits a single replica with a persistent volume; several
replicas must share one `SECRET_KEY`.

### Behind a proxy (TLS)

In production the defaults redirect plain HTTP to https and send HSTS. The
service itself speaks plain HTTP, so a TLS-terminating proxy must be in
front, and it must tell the service the original scheme:

- set `TRUSTED_PROXY` to the proxy's address(es) (or `*` when the service is
  reachable only through it). Then Django believes `X-Forwarded-Proto`
  (`SECURE_PROXY_SSL_HEADER`) and gunicorn accepts forwarded headers from
  those addresses. The proxy must set that header itself and drop any value
  sent by the client.
- without `TRUSTED_PROXY`, every request looks like plain HTTP and is
  redirected to https (a warning at startup says so). To serve plain HTTP
  deliberately (as `delonix-manifest.yaml` does on a local port), set
  `SECURE_SSL_REDIRECT=false` and `SECURE_HSTS_SECONDS=0`.

Health probes are answered before the redirect and before `ALLOWED_HOSTS`
validation, so a runtime can probe `http://127.0.0.1:__PORT__` directly.
HSTS preload stays off (it is a per-domain registration at hstspreload.org);
its deploy warning `security.W021` is silenced in `config/settings.py`, the
only silenced check.

## Database and migrations

- Default: SQLite in `db.sqlite3` (development) — one process group, one host.
- PostgreSQL: `uv add 'psycopg[binary]'`, then
  `DATABASE_URL=postgres://user:password@host:5432/name`. Connections are
  reused for 60 s and health-checked before use.
- Locally, migrations are an explicit step: `make migrate`.
- In the container, `docker/entrypoint.sh` applies them before gunicorn starts
  when `MIGRATE_ON_START=true`. The manifest sets it, because its default is
  one replica on SQLite; a failed migration stops the container before it
  listens.
- With several replicas, remove `MIGRATE_ON_START` (each replica would race to
  migrate) and run
  `delonix container exec __NAME__ /app/.venv/bin/python manage.py migrate`
  or a release job in a pipeline instead. gunicorn itself never migrates.
- Until they are applied, readiness answers 503
  `{"status":"unavailable","dependency":"migrations"}` and the replica gets
  no traffic. `make migrations-check` fails CI when a model changed without
  its migration.

## API

Base `http://localhost:__PORT__`. Contract: [api/openapi.yaml](api/openapi.yaml).
Every error has one shape: `{"error":{"code","message","fields"?,"request_id"}}`
with codes `validation_failed` (422), `malformed_json` (400), `body_too_large`
(413), `not_found` (404), `method_not_allowed` (405), `bad_request` (400, e.g.
a Host header not in `ALLOWED_HOSTS`), `internal` (500, no stack).

```bash
curl -si -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' \
  -d '{"title":"hello","body":"world"}'
# 201, Location: /api/v1/notes/<id>, {"id": "…", "title": "hello", "body": "world", "created_at": "…"}
curl -s 'localhost:__PORT__/api/v1/notes?offset=0&limit=20'
# {"items": […], "total": 1, "offset": 0, "limit": 20}      (newest first; limit 1–100)
curl -s -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' -d '{"title":""}'
# 422 {"error": {"code": "validation_failed", "message": "invalid input", "fields": {"title": "is required"}, "request_id": "…"}}
```

Bodies are parsed strictly: invalid UTF-8, duplicate keys, `NaN`, unknown
fields and non-objects are `malformed_json`. Versioning: breaking changes go
to `/api/v2`; `/api/v1` changes are additive. `tests/test_openapi.py` fails
when routes and contract drift.

CSRF: the API views are `csrf_exempt` (through `core.http.api_view`). They
serve non-browser clients and set or read no cookie, so there is no ambient
credential for a forged cross-site request to ride on. `CsrfViewMiddleware`
stays installed for any browser-facing view you add; if you add cookie/session
authentication to the API, remove the exemption.

## Webhooks (both directions)

Format: [Standard Webhooks](https://www.standardwebhooks.com) — headers
`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64 HMAC-SHA256>`
over `<id>.<timestamp>.<raw body>`.

- **Inbound** `POST /api/v1/webhooks/inbound` (404 without
  `WEBHOOK_INBOUND_SECRET`): verifies over the raw bytes (`request.body`),
  refuses timestamps more than 5 minutes off (replay window), compares in
  constant time, limits the body to 256 KiB. Events: `ping`, `note.create`
  (runs the same use case as the API). A repeated `webhook-id` is
  acknowledged (204) without being processed again: the id is stored under a
  unique key in the same transaction as the processing, so this holds across
  restarts and across replicas sharing the database, and a delivery whose
  processing failed is not recorded (its retry is processed).
- **Outbound** (only with `WEBHOOK_TARGET_URL`): each created note is sent as
  `note.created` after its transaction commits, `webhook-id` = note id (the
  receiver's idempotency key), 5 s timeout per attempt, up to 4 attempts with
  exponential backoff and full jitter on network errors, 429 and 5xx; other
  4xx are final. One background thread per gunicorn worker. Deliveries are
  counted in the `webhook.deliveries{outcome}` metric and logged.
- **Delivery semantics**: at-least-once while the process lives; at-most-once
  across a restart — events queued at shutdown are drained within
  `SHUTDOWN_TIMEOUT`, what remains is lost, as is everything queued when a
  worker is killed; a full queue (100 per worker) drops and counts. Never
  exactly-once. For durable delivery, see
  [docs/adr/0002](docs/adr/0002-webhooks.md).

Sign a test delivery by hand:

```bash
SECRET=whsec_$(head -c 32 /dev/urandom | base64); export WEBHOOK_INBOUND_SECRET=$SECRET
# restart the service, then:
ID=msg_1; TS=$(date +%s); BODY='{"type":"ping"}'
KEY=$(printf %s "${SECRET#whsec_}" | base64 -d | xxd -p -c 256)
SIG=$(printf '%s.%s.%s' "$ID" "$TS" "$BODY" | openssl dgst -sha256 -mac HMAC -macopt hexkey:$KEY -binary | base64)
curl -si -X POST localhost:__PORT__/api/v1/webhooks/inbound -H "webhook-id: $ID" \
  -H "webhook-timestamp: $TS" -H "webhook-signature: v1,$SIG" -d "$BODY"   # 204
```

## Logs, traces, metrics

- Logs: JSON on stdout, one line per event (the application's and
  gunicorn's), with `service`, `version`, `environment`, `request_id`, and
  `trace_id`/`span_id` inside a request. Fields whose name contains
  `authorization`, `cookie`, `password`, `secret`, `token`, `signature` or
  `api_key` are replaced by `[REDACTED]`. Query strings, headers and bodies
  are never logged. Health probes log at `debug`.
- Traces: one trace per request — the HTTP server span, a `notes.*` span for
  the use case, and `webhook.deliver` plus the outbound HTTP client span as
  children, so the outbound call (and its `traceparent` header) shares the
  request's trace id. Health probes are not traced.
- Metrics: the Django instrumentation's HTTP server metrics, httpx client
  metrics, and `webhook.deliveries`.
- Without `OTEL_EXPORTER_OTLP_ENDPOINT` nothing is exported, but trace ids
  still appear in logs. A collector that is down costs dropped batches and an
  SDK log line, not requests. Telemetry is configured per worker, after
  gunicorn forks (`config/wsgi.py`), because the SDK's export threads do not
  survive a fork. Maturity: traces and metrics are stable in the Python SDK;
  logs use the standard `logging` module, not the OTel logs bridge.

Local collector: [docs/runbooks/operations.md](docs/runbooks/operations.md#observability).

## Lifecycle

`/api/v1/health/live` answers 200 while the process runs.
`/api/v1/health/ready` is 503 `starting` until the worker has loaded the
application, 200 `ready`, 503 `unavailable` when the database does not answer
or migrations are pending, and 503 `draining` from SIGTERM. Readiness state
is per gunicorn worker; SIGTERM reaches all of them.

What happens on **SIGTERM** (measured, see
[docs/adr/0004](docs/adr/0004-gunicorn-lifecycle.md)): the gunicorn master
forwards it to every worker → each worker turns readiness to 503 and keeps
serving for `DRAIN_DELAY` → stops accepting and finishes in-flight requests →
drains the outbound webhook queue → flushes telemetry → exits. The worker
gives up on an undrained webhook queue inside the budget (logging `webhook
queue not drained at shutdown`), and gunicorn's master kills a worker still
running `SHUTDOWN_TIMEOUT` after the signal. The exit code is **0** in every
one of these cases — gunicorn does not report a cut shutdown in its exit
code; the logs do.

**SIGINT and SIGQUIT** are gunicorn's fast shutdown: workers stop at once,
without draining. `make dev` (`runserver`) has no graceful shutdown at all.

## Build and deploy with Delonix

```bash
delonix build -t __NAME__:dev .       # two stages; .dockerignore is honoured
delonix stack apply                   # a volume and the container; migrates at start
curl localhost:__PORT__/api/v1/health/ready
delonix stack destroy                 # removes what the manifest created
```

The manifest publishes `__PORT__` over plain HTTP, sets `APP_ENV=production`,
keeps SQLite and a generated `SECRET_KEY_FILE` on the `__NAME__-data` volume,
512M/1 CPU, a read-only root filesystem with a `/tmp` tmpfs, and
`restart: always`. The image installs from `uv.lock` when the project has one
and resolves otherwise (with a message).
It runs as the unprivileged user `app` (uid 10001), which owns nothing in the
image except `/data`, the mount point of the volume. The manifest names it
(`user:`) because the engine applies an image's USER only when asked — see
[docs/adr/0003](docs/adr/0003-container-image.md). Other engines can build
the `Delonixfile` as a Dockerfile, but only Delonix is the target here.

## Tests and CI

`make test` (pytest + pytest-django, in-memory SQLite) runs: use-case tests,
HTTP tests through Django's test client (happy path, every error class,
paging, body limit, request ids, readiness transitions and its database
checks), configuration tests (production refusals), webhook
signature/replay/duplicate tests, dispatcher retry/backoff/shutdown tests,
logging/redaction tests, the one-trace test (request → use case → outbound
call → log lines), the OpenAPI drift test and the architecture test. CI
(`.github/workflows/ci.yml`, `.gitlab-ci.yml`) installs with `--locked`
(failing with a message when `uv.lock` is not committed), runs `make check`'s
steps and `make vuln`, with a read-only token and actions pinned by SHA;
Dependabot updates Python dependencies, actions and the base image.

## On the internet without a public IP

`delonix-tunnel.yaml` opens an OUTBOUND tunnel: __NAME__ gets an `https`
address on the internet with no public IP, nothing opened on the router, and
no certificate to manage — the provider serves HTTPS with its own. It runs
only when applied; `stack apply` on `delonix-manifest.yaml` does not touch it.
Anyone on the internet can then reach the service.

Django answers only the hosts in `ALLOWED_HOSTS`, so first, in
`delonix-manifest.yaml`, add the tunnel's host to `ALLOWED_HOSTS`
(`.trycloudflare.com` for a quick tunnel — the leading dot covers its random
names — or your own domain) and set `TRUSTED_PROXY=*`, so the scheme the tunnel
reports (`X-Forwarded-Proto`) is believed (see "Behind a proxy (TLS)"). An env
change is not applied to a container that already exists, so recreate it:
`delonix container rm -f __NAME__`, then `delonix stack apply` (the data is on
the volume). `*` is safe here because the manifest publishes the port on
`127.0.0.1` only: the tunnel is the one way in from outside.

### Just a tunnel (no account, no domain)

1. Install `cloudflared` ([releases](https://github.com/cloudflare/cloudflared/releases),
   or your distribution's package) somewhere on `PATH`.
2. `delonix stack apply -f delonix-tunnel.yaml`
3. `delonix get gateways` — the address is in `PUBLIC URL`.

The address is random (`https://<words>.trycloudflare.com`) and changes every
time the tunnel opens; Cloudflare offers these quick tunnels for testing,
without an uptime guarantee. Close it with
`delonix delete gateways __NAME__-tunnel`.

### Your own domain (a stable address)

The domain's DNS has to be on Cloudflare (a free account is enough: point the
domain's name servers, at your registrar, to the two Cloudflare gives you).

1. Cloudflare dashboard → Zero Trust → Networks → Tunnels → **Create a
   tunnel** → Cloudflared. Name it and copy the token from the install
   command it shows (`--token eyJ…`).
2. In the tunnel, add a **public hostname**: `app.example.org` → service
   `http://localhost:__PORT__`. Cloudflare creates the DNS record.
3. Keep the token in a Delonix secret, typed in so it lands in no file and
   no shell history: run `delonix secret create __NAME__-tunnel --from-env-file -`,
   type `token=<the token>`, then Enter and Ctrl-D.
4. In `delonix-tunnel.yaml`, uncomment `tokenSecretRef` and `hostname`, then
   `delonix stack apply -f delonix-tunnel.yaml`.

Visitors get Cloudflare's certificate for `app.example.org`. To change the
route later, change it in the dashboard: with a token the tunnel takes its
routes from there, not from this file.

### Other providers

`provider:` also takes:

- `ngrok`: the ngrok agent on `PATH` and an account
  (`ngrok config add-authtoken <token>`). A free account has one fixed name
  (`<words>.ngrok-free.dev`): a stable address without a domain of your own.
  One ngrok tunnel at a time per machine.
- `pinggy`: nothing to install (plain `ssh`), a URL valid for 60 minutes, and a warning page shown to browsers before the site.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `ImproperlyConfigured: configuration: …` at start | an invalid variable — the message names each |
| CI fails with `uv.lock is missing` | run `uv lock` and commit the file |
| ready is 503 `"dependency": "migrations"` | run the migrations (`make migrate`) |
| every request answers 301 to https | production without `TRUSTED_PROXY`; see "Behind a proxy" |
| 400 `bad_request` on every request | the Host header is not in `ALLOWED_HOSTS` |
| `WEBHOOK_INBOUND_SECRET: … whsec_` | secret not in `whsec_<base64>` form, or under 24 bytes |
| inbound webhook answers 401 | wrong secret, body re-encoded by a proxy, or clock skew over 5 minutes |
| `/api/v1/webhooks/inbound` is 404 | `WEBHOOK_INBOUND_SECRET` is not set |
| no traces in the collector | `OTEL_EXPORTER_OTLP_ENDPOINT` unset, or not the `:4318` HTTP port |
