# __NAME__

A FastAPI service generated by `delonix init -t fastapi -v __TEMPLATE_VERSION__`
(pinned to `fastapi==__TEMPLATE_VERSION__.*`). It is a small, complete example — not a
skeleton: one business capability (notes) from HTTP request to storage port,
signed webhooks in both directions, OpenTelemetry traces and metrics, JSON
logs, a readiness state that follows the process lifecycle, and bounded
shutdown.

| | |
|---|---|
| Language / runtime | Python 3.13 (`.python-version`, `Delonixfile`) |
| Framework / server | FastAPI __TEMPLATE_VERSION__, Pydantic 2, Uvicorn |
| Tooling | uv (lock, environment, build), Ruff (format + lint), mypy `--strict`, pytest |
| Telemetry | OpenTelemetry SDK (traces, metrics), contrib FastAPI and httpx instrumentation |
| Storage | in memory (`notes/memory.py`) — replace for real use |
| Contract | `api/openapi.json` (OpenAPI 3.1, generated by FastAPI, checked in) |

Limits of the example, stated up front: notes live in memory and vanish on
restart; the inbound webhook de-duplication and the outbound queue are in
memory too (see [docs/adr/0002](docs/adr/0002-webhooks.md)); the server is one
process with one event loop (scale with replicas, not `--workers`: memory state
is per process). Nothing here authenticates API callers — add your platform's
mechanism before exposing it.

## Quickstart

Prerequisites: [uv](https://docs.astral.sh/uv/) 0.12 or newer (it installs
Python 3.13 itself); `make` and `curl`; Delonix to build and run the image.

```bash
make lock                         # resolve and write uv.lock — commit it (see below)
make check                        # install, format check, lint, mypy, tests, build
make run                          # python -m __MODULE__, listening on :__PORT__
make smoke                        # in another terminal → "smoke: OK"
# Ctrl-C (SIGINT) or SIGTERM → ordered shutdown, exit 0
```

`uv.lock` is not generated by `delonix init` (it never runs a package manager),
so the first step of a new project is `make lock` and a commit of `uv.lock`.
Everything else (`make install`, CI) installs with `--locked` and refuses to
run without it.

`uv.lock` together).

## Layout

```
src/__MODULE__/
  server.py              process entry: config, logging, telemetry, uvicorn, signals, exit code
  app.py                 composition root: adapters, use cases, routers, middleware, lifespan
  config.py              typed, validated settings (pydantic-settings)
  lifecycle.py           readiness state (starting → ready → draining)
  contract.py            generates api/openapi.json
  notes/                 the capability
    domain.py              Note, limits, domain errors            (standard library only)
    ports.py               NoteStore, NotePublisher (Protocols)   (standard library only)
    service.py             use cases                              (standard library only)
    memory.py              in-memory adapter of NoteStore
    api.py                 router, request/response schemas, dependency
  webhooks/
    signature.py, dedup.py Standard Webhooks sign/verify, replay memory (standard library only)
    api.py                 inbound endpoint
    dispatcher.py          outbound queue, retries, signing
  web/                   error shape, request id, access log, body limit, health routes
  observability/         JSON logging, OpenTelemetry setup, traced use-case decorator
tests/                   one file per concern; test_architecture.py holds the import rules
api/openapi.json         HTTP contract
deploy/otel-collector.yaml  local Collector for development
```

[ARCHITECTURE.md](ARCHITECTURE.md) has the dependency rules and a worked
example of extending the capability.

## Configuration

All from the environment (and `.env` in the working directory, for local
runs); validated at startup — every problem is listed, and the process exits 1
before listening. See [.env.example](.env.example). Durations accept `15`,
`15s`, `500ms`, `1m`.

| Variable | Purpose | Default | Required | Sensitive |
|---|---|---|---|---|
| `APP_ENV` | `development`, `test`, `production` | `development` | no | no |
| `LOG_LEVEL` | `debug`, `info`, `warning`, `error` | `info` | no | no |
| `SERVICE_NAME` | service name in logs and telemetry | `__NAME__` | no | no |
| `PORT` / `HTTP_HOST` | listen address | `__PORT__` / `0.0.0.0` | no | no |
| `HTTP_MAX_BODY_BYTES` | request body limit (413 beyond it) | `1048576` | no | no |
| `HTTP_KEEPALIVE_TIMEOUT` | idle keep-alive connections are closed after | `5s` | no | no |
| `SHUTDOWN_TIMEOUT` | bound of the whole shutdown | `15s` | no | no |
| `DRAIN_DELAY` | time serving with readiness at 503 before closing | `0s` | no | no |
| `WEBHOOK_INBOUND_SECRET` | `whsec_<base64>`; enables the inbound endpoint | — | no | **yes** |
| `WEBHOOK_TARGET_URL` | receiver of `note.created` (https in production) | — | no | no |
| `WEBHOOK_TARGET_SECRET` | `whsec_<base64>`; required with the URL | — | with URL | **yes** |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP/HTTP collector, e.g. `http://collector:4318` | — (no export) | no | no |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | sampling | SDK default (parent-based, always on) | no | no |
| `OTEL_SDK_DISABLED` | `true` disables telemetry | — | no | no |

`APP_ENV=production` turns the development conveniences off: the interactive
docs (`/docs`, `/redoc`, `/openapi.json`) are not served, and a plain-`http`
`WEBHOOK_TARGET_URL` is refused at startup. Secrets come from the environment
only: locally from `.env` (git-ignored), in Delonix from a secret
(`delonix secret create`, see the manifest comment). The `OTEL_*` variables
are read by the OpenTelemetry SDK from the process environment, not from
`.env`.

## API

Base `http://localhost:__PORT__`. Contract: [api/openapi.json](api/openapi.json);
outside production also browsable at `/docs`. Every error has one shape:
`{"error":{"code","message","fields"?,"request_id"}}`.

```bash
curl -si -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' \
  -d '{"title":"hello","body":"world"}'
# 201, Location: /api/v1/notes/<id>, {"id":"…","title":"hello","body":"world","created_at":"…"}
curl -s 'localhost:__PORT__/api/v1/notes?offset=0&limit=20'
# {"items":[…],"total":1,"offset":0,"limit":20}
curl -s -X POST localhost:__PORT__/api/v1/notes -H 'Content-Type: application/json' -d '{"title":""}'
# 422 {"error":{"code":"validation_failed","message":"invalid input","fields":{"title":"is required"},"request_id":"…"}}
```

| Code | Status | When |
|---|---|---|
| `validation_failed` | 422 | a field breaks a rule or has the wrong type; unknown fields are refused |
| `malformed_json` | 400 | the body is not JSON, or not a JSON object |
| `body_too_large` | 413 | body over `HTTP_MAX_BODY_BYTES` (announced or streamed) |
| `not_found` / `method_not_allowed` | 404 / 405 | no such note, route or method |
| `internal` | 500 | unexpected error; the detail is in the logs, never in the response |

Versioning: breaking changes go to `/api/v2`; `/api/v1` changes are additive.
`tests/test_openapi.py` fails when the routes and `api/openapi.json` drift.

## Webhooks (both directions)

Format: [Standard Webhooks](https://www.standardwebhooks.com) — headers
`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64 HMAC-SHA256>`
over `<id>.<timestamp>.<raw body>`.

- **Inbound** `POST /api/v1/webhooks/inbound` (answers 404 without
  `WEBHOOK_INBOUND_SECRET`): verifies over the raw bytes, refuses timestamps
  more than 5 minutes off (replay window), compares in constant time
  (`hmac.compare_digest`), acknowledges a repeated `webhook-id` without
  processing it again, limits the body to 256 KiB. Events: `ping`,
  `note.create` (runs the same use case as the API).
- **Outbound** (only with `WEBHOOK_TARGET_URL`): each created note is sent as
  `note.created`, `webhook-id` = note id (the receiver's idempotency key),
  5 s timeout per attempt, up to 4 attempts with exponential backoff and full
  jitter on network errors, 429 and 5xx; other 4xx are final. Deliveries are
  counted in the `webhook.deliveries{outcome}` metric and logged.
- **Delivery semantics**: at-least-once while the process lives; events queued
  at shutdown are drained within `SHUTDOWN_TIMEOUT`, what remains is lost; a
  full queue (100) drops and counts. Never exactly-once. For durable delivery,
  see [docs/adr/0002](docs/adr/0002-webhooks.md).

Sign a test delivery by hand:

```bash
SECRET=whsec_$(head -c 32 /dev/urandom | base64); export WEBHOOK_INBOUND_SECRET=$SECRET
# restart the service, then:
ID=msg_1; TS=$(date +%s); BODY='{"type":"ping"}'
KEY=$(printf %s "${SECRET#whsec_}" | base64 -d | xxd -p -c 256)
SIG=$(printf '%s.%s.%s' "$ID" "$TS" "$BODY" | openssl dgst -sha256 -mac HMAC -macopt hexkey:$KEY -binary | base64)
curl -si -X POST localhost:__PORT__/api/v1/webhooks/inbound -H "webhook-id: $ID" \
  -H "webhook-timestamp: $TS" -H "webhook-signature: v1,$SIG" -d "$BODY"   # 204
```

## Logs, traces, metrics

- Logs: JSON on stdout, one line per event, with `service`, `version`,
  `environment`, and inside a request `request_id`, `trace_id`, `span_id`.
  Extra fields whose key contains `authorization`, `cookie`, `password`,
  `secret`, `token`, `signature` or `api_key` are replaced by `[REDACTED]`.
  The access log has the path, never the query string, headers or bodies.
  Health probes log at `debug`. Uvicorn's and the SDK's own lines come out in
  the same format.
- Traces: one trace per request — the server span (`POST /api/v1/notes`), a
  `notes.*` span for the use case, and `webhook.deliver` plus the outbound
  HTTP client span as children, so the outbound call carries the request's
  trace id in `traceparent`. Health probes are not traced. The server span is
  the contrib instrumentation's: its `http.url` attribute includes the query
  string, so do not put secrets in query parameters.
- Metrics: HTTP server and client metrics from the instrumentations, labelled
  by route template (never by raw path), and `webhook.deliveries`.
- Without `OTEL_EXPORTER_OTLP_ENDPOINT` nothing is exported, but trace ids
  still appear in logs. A collector that is down costs dropped batches and
  warning lines, not requests, and at most 5 s at shutdown. Maturity: traces
  and metrics are stable in the Python SDK; logs go through `logging`, not the
  OpenTelemetry logs SDK (still experimental in Python); the contrib
  instrumentation packages are versioned as betas (`0.NNbN`).
- FastAPI 0.142 added its own OpenTelemetry integration. It is switched off in
  `app.py`: left on next to the contrib instrumentation it attaches a second
  exporter and every span is exported twice. See
  [docs/adr/0001](docs/adr/0001-structure.md).

Local collector: [docs/runbooks/operations.md](docs/runbooks/operations.md#observability).

## Lifecycle

`/api/v1/health/live` answers 200 while the process runs. `/api/v1/health/ready`
is 503 `starting` until the application has started, 200 `ready`, and 503
`draining` from the first SIGTERM/SIGINT. Shutdown order, all within
`SHUTDOWN_TIMEOUT`: readiness → `DRAIN_DELAY` (still serving) → stop accepting
and finish in-flight requests → drain the webhook queue → flush telemetry.
Exit 0 when that completed, 1 when the deadline cut it (requests still running
are cancelled and answered 500). A second Ctrl-C skips the wait. `make dev`
uses uvicorn's reloader and its plain shutdown instead. No persistence, so no
migrations.

## Build and deploy with Delonix

```bash
delonix build -t __NAME__:dev .       # two stages; .dockerignore is honoured
delonix stack apply                   # delonix-manifest.yaml
curl localhost:__PORT__/api/v1/health/ready
delonix stack destroy                 # removes what the manifest created
```

The image installs from `uv.lock` when the project has one and resolves
otherwise (printing that it did). The runtime stage holds only the virtual
environment: no uv, no tests, no `.env`. The manifest publishes `__PORT__`,
sets `APP_ENV=production`, 512M/1 CPU, read-only root filesystem with a `/tmp`
tmpfs, and `restart: always`. The image runs as uid 0 inside the container;
with rootless Delonix that uid is your unprivileged host user, which is not
the same as a non-root user inside the container — see
[docs/adr/0003](docs/adr/0003-container-image.md). Other engines can build the
`Delonixfile` as a Dockerfile.

## Tests and CI

`make test` runs: use-case tests, HTTP tests through the whole middleware
stack (happy path, every error class, pagination, body limit, readiness
transitions), webhook signature/replay/duplicate tests (including the Standard
Webhooks reference vector), dispatcher retry/backoff/shutdown tests, the
one-trace test (request → use case → outbound call → log lines), the contract
drift test and the architecture test. Warnings are errors. CI
(`.github/workflows/ci.yml`, `.gitlab-ci.yml`) runs `make check` and
`make audit`, with a read-only token and actions pinned by SHA, and fails with
the reason when `uv.lock` is missing; Dependabot updates the Python
dependencies, the actions and the base image.

### Upgrading

`uv lock --upgrade` moves every dependency inside its range (FastAPI stays on
`__TEMPLATE_VERSION__.*`). To move to another FastAPI minor, change the pin in
`pyproject.toml`, run `make lock check`, and `make openapi` if the generated
contract changed. Tested with FastAPI 0.141 and 0.142.

## Troubleshooting

| Symptom | Cause |
|---|---|
| `uv.lock is missing` | run `make lock` and commit `uv.lock` |
| exits with `configuration:` and a list | an invalid variable — the message names each |
| `WEBHOOK_INBOUND_SECRET: … whsec_` | secret not in `whsec_<base64>` form, or under 24 bytes |
| inbound webhook answers 401 | wrong secret, body re-encoded by a proxy, or clock skew over 5 minutes |
| `/api/v1/webhooks/inbound` is 404 | `WEBHOOK_INBOUND_SECRET` is not set |
| `api/openapi.json is stale` in tests | a route or schema changed: `make openapi`, review the diff |
| no traces in the collector | `OTEL_EXPORTER_OTLP_ENDPOINT` unset, or not the `:4318` HTTP port |
| `/docs` is 404 | `APP_ENV=production` |
