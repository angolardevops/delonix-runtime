There is one maintainer today. That is a fact about this project's current size, not a target —
see [GOVERNANCE.md](GOVERNANCE.md) for how a second maintainer would be added, and for what
happens to a decision while there is only one.

## Becoming a maintainer

Not a form to fill in — a track record. Sending correct, well-tested PRs that touch the
harder parts of this codebase (the namespace/cgroup boundary, the network dataplane, the
manifest reconciler) and following through on review is what gets noticed. If that happens
consistently, the existing maintainer(s) will offer it — see
[GOVERNANCE.md](GOVERNANCE.md#adding-a-maintainer).

## Stepping down

Open an issue saying so, and update this file in the same PR. No process beyond that: a
maintainer who has left should not stay listed as one.
